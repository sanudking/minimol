# MiniMoL 0.6.0 implementation status

## Implemented in this release

- **STUN-assisted ICE:** two STUN discovery endpoints are configured. There is no TURN server and no signaling backend.
- **QR signaling:** offer and answer are still exchanged by QR. QR canvas remains 320 × 320 px and CSS display remains capped at 300 × 300 px.
- **Complete ICE gathering:** offer/answer QR creation waits up to 25 seconds for ICE gathering to finish. If it does not finish, QR generation stops with an explicit error rather than encoding an incomplete candidate list. This is important because there is no signaling service to deliver late trickle candidates.
- **Actual CPU worker parallelism:** with cross-origin isolation and `SharedArrayBuffer`, each phone creates a small pool of dedicated Web Workers. Large matrix-vector products are split across output-row ranges. Each output row keeps the same FP32 multiply/add order as the serial implementation.
- **Safe fallback:** when `SharedArrayBuffer`, COOP/COEP, or nested workers are unavailable, inference falls back to serial JavaScript inside the existing inference worker. UI remains off the compute thread.
- **Protocol compatibility guard:** app protocol version is incremented so a 0.5.x phone cannot silently pair with this release.
- Existing 32-byte reference integrity challenge, three-trial benchmark, and batched prompt-prefill path are retained.

## Deployment requirement for multithreading

The deployment must send these headers on the app and worker scripts:

- `Cross-Origin-Opener-Policy: same-origin`
- `Cross-Origin-Embedder-Policy: require-corp`
- `Cross-Origin-Resource-Policy: same-origin`

They are configured in `netlify.toml` and `vercel.json`. After deployment, the device load status reports whether the parallel worker kernel actually started or whether the serial fallback is active.

## Deliberately not claimed / not implemented

- **Speculative top-1 pipeline lookahead:** Phone 1 does not know the next byte until Phone 2 completes layers 3–5 and the output head. Precomputing an exact next activation before receiving that byte is impossible without guessing; a guess can miss and must be validated. No 0.04 ms exact-latency claim is made.
- **Custom WASM kernel:** not included. A genuine WASM implementation needs its own numerical parity tests and mobile profiling.
- **Int8 activation transport:** not enabled. Quantization changes intermediate values and can change greedy output; it must be an explicitly selected lossy mode with separate accuracy measurements, not the default integrity path.
- **Full-sequence mode, one-byte mode switcher, weight export/upload UI, three-way JS/WASM determinism suite, and signed benchmark certificate:** not included in this release.
- **No performance figure is asserted.** Worker startup, SharedArrayBuffer copying, and message scheduling can make parallel execution slower for some phones or small operations. Measure on the target devices before claiming a tokens/sec gain.

## Verification performed in this workspace

- `node --check` passed for the application, engine, inference worker, matrix-vector worker, and scripts.
- `npm run verify` passed: 32 generated byte IDs matched `reference_outputs.json` on the serial Node verification path.
- Vite production build was not verified in this Linux workspace because the supplied dependency tree was macOS-arm64-specific and the registry install timed out. Run `npm install && npm run build` on the deployment machine before publishing.
- Physical two-phone STUN/ICE and multithread performance testing remains required.
