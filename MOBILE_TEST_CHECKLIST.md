# MiniMoL — two-device acceptance checklist

## Before pairing
- [ ] Same HTTPS deployment opened on both phones.
- [ ] Phone 1 role selected on one phone; Phone 2 on the other.
- [ ] Each phone shows READY after loading its own partition.
- [ ] Both partitions passed SHA-256 validation.
- [ ] Both phones are on the same non-guest Wi-Fi/LAN for the first test.

## QR pairing
- [ ] Phone 1 creates and displays an offer QR.
- [ ] Phone 2 camera permission is granted and scans the offer QR.
- [ ] Phone 2 creates and displays an answer QR.
- [ ] Phone 1 scans the answer QR.
- [ ] Both phones show CONNECTED after ICE and role/model handshake.
- [ ] If ICE fails, try same Wi-Fi and check router/AP client isolation. STUN is configured; TURN is not.

## First inference
- [ ] Start with a short prompt and 4–8 generated bytes.
- [ ] Start generation from Phone 1.
- [ ] Confirm Phone 2 changes to RUNNING, then COMPLETE.
- [ ] Confirm both CPU metrics update and generated bytes appear on Phone 1.
- [ ] Confirm disconnect/worker errors are surfaced instead of leaving the UI stuck.

## Offline check
- [ ] Complete first page load and model partition caching on both phones.
- [ ] Disable internet but keep both phones on the same local Wi-Fi.
- [ ] Reopen the HTTPS origin on both phones.
- [ ] Confirm each phone restores its partition from IndexedDB.
- [ ] Pair again using fresh QR codes and run a short generation.

## Hackathon feature checks (v0.5.0)
- [ ] Confirm both phones show the same protocol release and connect through QR.
- [ ] Confirm heartbeat RTT appears on both devices and recovers after a brief Wi-Fi interruption.
- [ ] Generate at least 32 bytes; confirm the execution map advances and both processed-position counters increase.
- [ ] Run the 32-byte integrity challenge; expect `PASS · 32/32` on the Phone 1 screen.
- [ ] Run the three-trial benchmark on the same device pair and record median/p95 tok/s.
- [ ] Compare performance only after both phones cool down and background apps are closed.
